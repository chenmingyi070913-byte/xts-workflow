# xts-workflow：兴头上工作流库

这个仓库放兴头上团队的工作流程和每轮进度。它回答两个问题：我们怎么做，这一轮做到哪一步。
做出来的成果放在另一个仓库 [xts-library](https://github.com/chenmingyi070913-byte/xts-library)。

本轮进度：V8 轮次已建立，各节点本轮未跑。详情见 `本轮进度.md`。

## 这个库放什么
- 当前在用的产品工作流系统：协议、岗位说明、skill。
- 每一轮的轮次记录、对话、交接和执行记录。
- 流程版本记录、变动登记和长期记忆。
- 工作流方法本身的试跑和研究。

## 这个库不放什么
- 产品成果，它们放在 xts-library。
- 个人日记和私人生活材料。
- 账号、密码、密钥和任何凭据。
- 外部仓库的整份副本。外部仓库只记链接和提交号。

## 周和时间
- 时间一律用北京时间（GMT+8）。
- 每周从周四开始，到下周三结束。周三开例会。
- 一周一轮。轮次编号直接用周版本号：V8 这一周的轮次放在 `轮次/V8/`。同一周的多次执行放在 `runs/` 下，各有 run_id。

## 版本号
- 流程版本号按方法走：0.4.0、0.5.0，沿用 Codex 现有编号。
- 流程本身被修订、经团队在例会上采用时才升版本，`CHANGELOG.md` 写生效日期。
- 流程版本号和成果库的周版本号（V1、V1.2 这类）互相独立。流程升版只改这个仓库，成果库的旧成果保留当时的流程版本标记。

## 权威规则
1. `方法/` 里放的是当前在用的流程，其他版本只作参考。
2. 每周三例会后，上一轮的成果失去权威；轮次记录本身保留，不再修改。
3. 规则和实际不符时，先记进 `变动登记.md`，当周照实际做。同一处偏离连续两周出现，再出候选版，例会上采用后升版本。
4. 可复用候选的验证是工作流里的固定节点，每周都跑。验证记录留在当轮 runs/ 里，通过的内容写进 xts-library 的 `30_可复用库/`。可复用库只当素材。

## 目录
```

AGENTS.md          AI 读取规则；一个对话只担任一个岗位
CHANGELOG.md       流程版本记录
本轮进度.md        给团队看的一页进度
变动登记.md        规则和实际不符时的记录
长期记忆.md        已确认的决定和可复用经验
方法/              协议、岗位说明、skill
轮次/              索引.md 和每周一个轮次文件夹
方法实验/          工作流方法本身的试跑
研究/              工作流方法研究
```
